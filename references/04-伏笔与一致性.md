# 04 · 伏笔与一致性

覆盖九步工作流 **⑥ 落追踪的伏笔部分** 与 **⑦ 审校的连续性检查**。

**核心判断**：伏笔丢失不是记性问题，是**没有账本**。写到第 200 章时，第 12 章埋的那块玉佩你一定记得——除非它当时没进账。凡**没记进账本的伏笔，等于不存在**。

---

## 1. 伏笔账本：字段定义

账本在总表里有真源（`追踪/总表.md` 的「伏笔账本」区），`追踪/伏笔账本.md` 是**派生视图**，由总表重渲染（铁律一）。

| 字段 | 原项目对应 | 填法 | 硬规则 |
|---|---|---|---|
| `ID` | `element_id` | `F001` 起顺排，不用语义 ID | **创建后永不改号**，作废也保留行 |
| `类型` | `element_type` | 物件 / 台词 / 人物 / 设定 | 见 §2 |
| `埋于` | `planted_chapter` | 首次出现的章号 | 必须是**已写完**的章 |
| `摘要` | `description` | 一句话：埋的是什么 | 写成读者读到的样子，不是作者真相 |
| `提示` | `hints[]` | 每次再提一次的（章号 + 内容） | 追加，不覆盖 |
| `计划回收` | `payoff_planned_chapter` | 打算第几章回收 | **待定填 `待定`**，不填 0、不瞎填 |
| `实际回收` | `payoff_delivered_chapter` | 真正回收的章号 | 只能填**已发生**的章 |
| `结局说明` | `resolution` | 回收后兑现成什么 | 未回收留空 |
| `状态` | `status` | `已埋` / `部分揭示` / `已回收` / `作废` | 见状态机 |
| `重要度` | 本技能包新增 | 高 / 中 / 低 | 决定过期时先处理谁 |

### 状态机

```
已埋 ──再提一次──> 已埋（提示+1）
  │
  ├──> 部分揭示 ──> 已回收
  │
  └──> 作废（登记理由，行保留，不再报警）
```

**两条纪律**
1. **未来计划不进账本**。「第 80 章揭示」写进卷纲/细纲，账本只填已经发生的章号（与铁律四同源）。
2. **作废要写理由**。删行等于抹掉历史，下一卷会再埋一个一模一样的。

## 2. 四种伏笔类型与埋法

| 类型 | 埋的是什么 | 埋法要点 | 典型回收 | 常见翻车 |
|---|---|---|---|---|
| **物件** | 玉佩、断剑、一枚铜钱、一本残页 | 埋时给它**一个不重要的用途**（垫桌脚、抵酒钱），读者才会忘 | 关键时刻它有用 | 埋得太郑重，读者一直在等，回收反而平 |
| **台词** | 一句承诺、一句威胁、一句随口的话 | 让说话的人**自己不当回事**，旁边有人记下了 | 说话人被要求兑现 | 埋成"预言腔"，读者一眼看穿 |
| **人物** | 一个路过的人、一个提过名字的长辈 | 给**一个具体动作或特征**，不给身份 | 后期揭身份/倒戈/救命 | 只提名字没有画面，回收时读者不认识 |
| **设定** | 一条规矩、一个禁忌、一句门规 | 通过**后果**展示（某人犯规当场受罚），不做说明 | 主角用它破局或反被它困 | 埋成设定说明，读者跳过不读 |

> 原项目另有 `chekhov_gun / mystery_box / prophecy / promise / red_herring` 五类划分，本技能包按**埋的载体**重新切分（载体决定埋法，功能不决定埋法）。需要标记"这是烟雾弹"时，在摘要里加 `[烟幕]`。

### 埋一条伏笔的最小动作（写进细纲就够）

```
① 选载体（上述四类之一）
② 定用途：这一章它顺手干了什么（不能是"主角注意到它很特别"）
③ 定回收：哪一章、兑现成什么、改变什么局面
④ 进账本：填 ID/类型/埋于/摘要/计划回收/已埋
```

## 3. 三类扫描（每章收尾必跑）

扫描纯靠**数字比较**，不需要理解正文——这是它能被脚本化、也不会看走眼的原因。

| 扫描项 | 判据 | 原项目判据 | 级别 |
|---|---|---|---|
| **过期伏笔** | `状态 ∈ {已埋, 部分揭示}` 且 `计划回收 ≠ 待定` 且 `当前章 > 计划回收 + 5` | 同（原项目就是 `+5`） | warning |
| **临期伏笔** | 同上但 `|计划回收 − 当前章| ≤ 10` | 同 | info（提醒准备） |
| **失活角色** | `当前章 − 角色最后出场章 > 15` | 原项目用 `> 20`，本技能包收紧到 **15**（网文日更密度高，20 章读者已经忘了） | info |
| **章节缺口** | 章节序号排序后存在 `相邻差 > 1` | 同 | warning |
| **无计划伏笔** | `状态 = 已埋` 且 `计划回收 = 待定` 且 `已埋超过 30 章` | 本技能包新增 | info |

### 判定顺序

```
① 取当前章号（总表「已提交至」）
② 逐条算：已埋/部分揭示的伏笔 → 过期？临期？无计划？
③ 逐人算：角色最后出场章 → 失活？
④ 排章节序号 → 有缺口？
⑤ 出报告（模板见 §5）
```

**报警不等于要改稿**：过期伏笔有三种出路，见 §4。

---

## 4. 过期伏笔的三条出路

| 出路 | 适用 | 动作 | 账本怎么记 |
|---|---|---|---|
| **提前回收** | 重要度＝高，且近期有合适场次 | 在下一章细纲里加一个回收情节点 | 改 `计划回收` 为新章号，回收后填 `实际回收` |
| **顺延** | 重要度＝中/低，但舍不得扔 | 改 `计划回收` 到新的章号 | **只改计划，不改状态**；同时在本章加一次 `提示`，让读者别忘 |
| **作废** | 剧情改道，这条已经不成立 | 状态改 `作废`，写清理由 | 行保留、不再报警；正文里若已埋，最好让它在某处**落空**（读者看到"原来没用"，比无声消失强） |

**不要做的事**：为了消掉报警而在正文里硬塞一次回收——那会写出"这章突然冒出个无关物件"的坏情节。报警是**提醒你做决定**，不是逼你塞。

## 6. 连续性自检清单

扫描管**数字**，这一节管**事实**。写完一章逐项打勾。

### 6.1 六项逐章必查（取自 Chinese-WebNovel-Skill）

| # | 项 | 要回答的问题 |
|---|---|---|
| 1 | **剧情逻辑** | 本章最关键的事件，前提够不够？最关键的决定，触发够不够？事件后局面有没有实质变化？ |
| 2 | **目标一致** | 主角本章目标清楚吗？过程中有没有无故偏移？ |
| 3 | **情绪与关系** | 情绪有触发和过渡吗？关系状态和上一场接得上吗？ |
| 4 | **身体与信息** | 伤势、疲劳、药效、秘密、误会、已知线索有没有丢？ |
| 5 | **场景与转场** | 读者会迷路吗？时间、空间、视角清楚吗？上一场的余力有没有带过来？ |
| 6 | **章末承接** | 章末收在变化上了吗？下一章第一拍接得住吗？ |

> **任意两项不稳，不要直接交稿。** 这是硬闸门，不是建议。

### 6.2 六个最常错的具体项

| 项 | 检查动作 | 典型翻车 |
|---|---|---|
| **时间线** | 本章故事内时间 vs 上章；"三天后"是否装得下发生的事；并行线是否同步 | 上章还在腊月，这章冒出蝉鸣 |
| **人称/视角** | 全章视角是否统一；视角人物能否看见他所描述的 | 第三人称限知里写了别人心里的想法 |
| **地名/方位** | 与术语表逐字对；河在城市哪一侧、路走几天 | 同一条街两个名字（同物异名＝违反术语表纪律） |
| **能力值/等级** | 与 `设定/金手指.md` 和上一章数值对；升级有没有写清过程 | 上章练气三层，这章直接筑基 |
| **伤势** | 上章受的伤这章是否还在影响动作；好了要有交代 | 断臂的人这章攀墙 |
| **物品归属** | 物件在谁手上；换了手有没有写清交接 | 玉佩上一章给了师妹，这章还在主角怀里 |

### 6.3 与铁律四联动的检查（最容易漏）

- 本章**角色的台词**里，有没有出现「读者已知」之外的信息？
- 本章**叙述**（尤其限知视角的内心）有没有提前说出答案？
- 本章有没有把「作者真相」里的东西写成角色的**常识**？

> 一句话：角色只能说读者已知范围内的。查完 §6.2 再查这一条，能拦掉"角色提前说漏答案"这类最难自查的错。

## 7. 什么时候跑

| 时机 | 跑什么 |
|---|---|
| **每章收尾**（不隔夜） | §3 三类扫描 + §6.1 六项 |
| **每卷末** | 全量扫描 + 逐条复核活跃伏笔是否该回收 |
| **改稿后** | 该章标脏 → 重渲染派生 → 重跑扫描（见 `03-追踪与状态.md` §5） |
| **续写前** | 只读派生账本，不重跑；发现脏标记先收敛 |

**顺序**：先更新总表 → 再重渲染派生 → 最后跑扫描。倒过来会把还没进真源的变化冲掉。
