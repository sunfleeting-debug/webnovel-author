# 09 · 批量写作

覆盖九步工作流 **⑨ 批量产出（可选）**。

**适用**：用户要一次性产出远超单轮输出上限的正文（"把第一卷 60 章都写了"＝十几万字）。
**不适用**：单章写作（走 ⑤⑥）、还没定大纲的项目。
⑨ 不豁免任何一条铁律，只是把 ⑤ 的执行换成多支笔；**细纲门禁（铁律二）在批量模式下是硬前提**。

## 1. 四步总览

**① 细纲契约 → ② 写《写作规范》→ ③ 分段 spawn 子代理并行（每批 8–10 章，prompt 自包含）→ ④ 🔴 事后统一校对 → 合并交付**
---

## 2. 第 1 步：细纲必须是"接口契约"

每章要给：**章号 + 标题 + 1–3 句内容 + 伏笔埋/收 + 出场人物 + 地点 + 本章变化 + 章末钩子 + 字数带**（九字段模板见 `02-细纲门禁.md`）。
**为什么必须是契约**：多支笔之间没有共同上下文。细纲写"打一场"，A 段写成单挑、B 段写成群殴；细纲写"他终于答应了"，谁也没说答应了什么。

> 实测坑：**细纲自己也会写错**（如"第五次模拟"实为第四次），子代理会照实写出并反馈回来。**它反馈的矛盾要当真**，逐条回改细纲/总纲，否则文档之间会长期打架。
---

## 3. 第 2 步：为什么必须先立《写作规范》

并行写作唯一的失败模式是**串味**。所有子代理共享的不是上下文，而是这份文件——它是唯一的"公共权重"。

| 要锁的东西 | 不锁会怎样 | 具体锁什么 |
|---|---|---|
| **文风硬要求** | 每段像不同人写的，追更读者立刻察觉 | 视角、句长/段长、每章字数区间、章末必须留钩子、标点习惯（全角标点、引号形态二选一） |
| **术语表** | 同物异名（"灵力/灵气/真元"随机出现），设定崩 | 专有名词、境界体系、金手指规则编号，**一个都不许改名** |
| **人物表** | 性格漂移、口头禅消失 | 每人：定位 + 口头禅 + 说话方式 + 结局定位 |
| **已定稿事实** | 与前文冲突（死人复活、断剑重挂） | **不可矛盾的事实清单**，含"读者已知"边界（铁律四） |
| **铁律** | 子代理为省事写成摘要 | 必须写完整正文（禁止摘要化）、不许跳章/合并/改标题、伏笔写法要求、**禁止作者视角的元叙述** |
| **输出格式** | 合并时格式乱成一锅粥 | `# 第X章 标题` + `---` 分隔，文件名 `第NNN章.md` |
| **数值账目**（附录） | 面板 / 资源 / 等级各自发挥，前后打架 | 逐章列出等级、金币、关键道具、"第 N 次模拟"，作为**唯一官方账目** |

### 可复制：《写作规范》骨架

```markdown
# 《{书名}》写作规范 · 并行执行版
> 本文件是多个并行写手之间唯一的共享上下文。请完整读完再动笔。

## 1 文风
视角={第三人称限知，只跟主角}　句长={平均 20–30 字，动作场面 10–15 字}　每章={2200–2800 字，不得低于 2000}
章末=必须停在**变化或新问题**上，不许抒情总结　标点=中文全角，引号「」或""二选一，全文一致

## 2 术语表（不许改名，不许自造同义词）
| 词 | 含义 | 禁用替代词 |
|---|---|---|
| {灵力} | {修炼所得的可消耗能量} | 灵气 / 真元 / 法力 |

## 3 人物表
| 角色 | 定位 | 说话方式 / 口头禅 | 结局定位 |
|---|---|---|---|
| {苏明} | {落魄外门弟子} | {话短、爱用反问句、"成"} | {卷末成为内门} |

## 4 不可矛盾的事实（截至第 {N} 章）
1. {苏明的剑已断，只剩半截}　2. {读者尚不知道老周是幕后}

## 5 铁律
1. 写**完整正文**，禁止摘要化、梗概化、"（此处略）"
2. 不许跳章、不许合并章节、**不许改标题**
3. 不许出现作者视角的话："第 X 章里""上文提到""读者都知道"
4. 伏笔要**写进动作和物件**，不许写"仿佛预示了什么"这种提示

## 6 输出格式
每章一个文件 `正文/第NNN章.md`；首行 `# 第NNN章 {标题}`（标题照抄细纲，一字不改）；章间用 `---` 分隔。

## 7 附录：数值账目（官方）
| 章 | 等级 | 金币 | 关键道具 | 模拟次数 |
|---|---|---|---|---|
| 41 | 三阶 | 1,200 | 断剑（半截） | 第 4 次 |
```

## 4. 第 3 步：分段并行 spawn

### 4.1 粒度（🔴 决定质量的参数）

| 每子代理负责 | 会发生什么 | 结论 |
|---|---|---|
| 1–3 章 | 每个子代理都要重读规范与前文，开销大于产出；每段开头重复铺垫 | 不用，浪费并发 |
| **8–10 章** | 摊薄启动成本，又短到来不及偷工减料 | **默认粒度** |
| 15 章以上 | 后半段写成摘要、场面缺斤两、字数塌方 | 不用 |

### 4.2 prompt 必须自包含（子代理看不到主对话）

每个子代理的 prompt 必须写清：

- [ ] 要读的**文件绝对路径**：`写作规范.md`、`大纲/细纲_第NNN-MMM章.md`、前一段正文文件
- [ ] 负责的**章号区间**与每章标题（照抄细纲）
- [ ] **输出文件路径**与格式
- [ ] 特别提示：哪几章是高燃 / 高泪 / 喜剧点 / 卷末高潮
- [ ] 收尾要求（钩子指向下一批）
- [ ] **先读完上一批最后 1–2 章正文再动笔**——细纲给事件，那两章给句调和当下处境，这是最便宜的衔接保险

### 4.3 执行顺序与失败处理

- 先跑第 1 段，**验收通过**再并行第 2 段起：第一段是风格锚，写歪了整批返工。
- 同一文件的多处修改必须**串行**（别并行 Edit 同一个文件）。
- 子代理撞频率限制（429）：换 `model` 参数重试（如 `reasoning`），不同模型配额独立。
- 每段回来立刻跑 `grep -c '^# 第'` 核章数，缺章就补，别攒到最后。

### 4.4 子代理 prompt 模板（可直接改）

```markdown
你是本项目第 {2} 段的写手。先完整读完下面三个文件，再动笔：
1. {绝对路径}/写作规范.md   ← 必读，术语与铁律以它为准
2. {绝对路径}/大纲/细纲_第{NNN}-{MMM}章.md
3. {绝对路径}/正文/第{NNN-1}章.md 和 第{NNN-2}章.md  ← 上一批最后两章，对接口吻与本段起始处境

任务：写 第 {NNN} 章 到 第 {MMM} 章，共 {K} 章，输出到 {绝对路径}/正文/ 下，
每章一个文件 `第NNN章.md`，首行 `# 第NNN章 {标题}`，标题照抄细纲一字不改。

硬要求：
- 每章 {2200–2800} 字，完整正文，不许摘要化、不许"（此处略）"
- 不许跳章、合并、改标题；术语一律用规范里的写法
- 不许写作者视角的话（例："第45章那把刀""上文提到""读者都知道"）
- 章末停在变化或新问题上
- 第 {X} 章是{本段高燃点}，第 {Y} 章是{本段高泪点}，这两章给足篇幅

写完后自查：① 章数对不对；② 每章字数达标否；③ 有没有违反术语表。
```

## 5. 第 4 步（🔴 必做）：事后统一校对

**并行写出来的稿子不能直接交付。** 以下是并行的稳定副作用，不是偶发 bug。

### 5.1 ① 引用章节号的元叙述（最高频，读者直接出戏）

子代理知道自己在写"第 45 章"，于是写出**作者视角**的话，读者读到立刻出戏。

| 出现的话 | 改成（故事内指代） |
|---|---|
| "第45章那把刀" | "那把断剑" / "石壁上崩断的那半截" |
| "想起第8章发生的事" | "想起上个月山洞里的那件事" |
| "正如上文提到" | 删掉，用动作或对话带出 |
| "这在前文已经铺垫" | 删掉（这是写给作者看的） |

```bash
grep -nE '第[0-9一二三四五六七八九十百]{1,5}章' 正文/全卷.md | grep -vE '^[0-9]+:# 第'
grep -nE '上文|前文|如下所述|读者都|在{0,1}第.{1,8}章里' 正文/全卷.md
```

### 5.2 ② 面板 / 数值各自发挥

多个写手各自推账，必然打架（同一个金币数在两段对不上、"第五次模拟"变成第四次）。

**做法：先定官方账目，再逐处对齐。**
1. 把《写作规范》附录的**数值账目表**填到本批所有章；
2. grep 出所有数值与账目表比对；
3. **以账目表为准改正文**；例外：某处偏离是更合理的剧情（中间多打了一场），那就改账目表并同步全部受影响章节。

```bash
grep -nE '[0-9]+ *(枚|块|两|点|级|层|阶|星|次)' 正文/全卷.md | sort -t: -k2
grep -nE '等级|经验|金币|灵石|积分|剩余次数' 正文/全卷.md
```

### 5.3 ③ 章号格式、缺号重复、尾注残留

| 症状 | 原因 |
|---|---|
| 中文数字与阿拉伯混用（`第四十一章` vs `# 第41章`） | 子代理把"不许改标题"理解成"不许动标题格式"，不会主动统一。统一用脚本（命令 ⑤）；纯中文数字标题搜不出来，要单独 `grep -nE '^# 第[一二三四五六七八九十百]+章'` |
| 缺号 / 重复号 | 某段跳了一章或多写了一章 |
| `（第X章 完）`、`未完待续`、`(本章完)` | 子代理自带仿站习惯，粘了尾巴 |

## 6. 可直接复用的命令（Git Bash / macOS / Linux）

```bash
# ① 按章号数字序合并（避免 第10章 排到 第2章 前）
python -c "import re,glob;fs=sorted(glob.glob('正文/第*章.md'),key=lambda p:int(re.search(r'第(\d+)章',p).group(1)));open('正文/全卷.md','w',encoding='utf-8').write('\n\n'.join(open(f,encoding='utf-8').read().strip() for f in fs)+'\n')"

# ② 核对章数
grep -c '^# 第' 正文/全卷.md

# ③ 重复章号（有输出＝重复）
grep -o '^# 第[0-9]\+章' 正文/全卷.md | grep -o '[0-9]\+' | sort -n | uniq -d

# ④ 缺号（输出形如 "缺口 58 -> 60"）
grep -o '^# 第[0-9]\+章' 正文/全卷.md | grep -o '[0-9]\+' | sort -n \
  | awk '{if(NR>1 && $1!=p+1) print "缺口", p, "->", $1; p=$1}'

# ⑤ 统一章号格式（只改标题行）
python -c "import re;p='正文/全卷.md';s=open(p,encoding='utf-8').read();s=re.sub(r'(?m)^#\s*第\s*([0-9]+)\s*章[ 　]*',lambda m:'# 第%s章 '%int(m.group(1)),s);open(p,'w',encoding='utf-8').write(s)"

# ⑥ 尾注残留
grep -nE '（第.{1,8}章 *(完|完结)?）|\(第.{1,8}章|未完待续|本章完|（完）|\(完\)' 正文/全卷.md

# ⑦ 逐章中文字数
for f in 正文/第*章.md; do printf '%s\t' "$f"; python -c "import re,sys;print(len(re.findall(r'[\u4e00-\u9fff]',open(sys.argv[1],encoding='utf-8').read())))" "$f"; done
```

> Windows Git Bash 下若报编码错，先 `export LC_ALL=C.UTF-8`。合并用 `cat` 或上面的 ① 拷贝，**不要**用 bash here-string 写含反引号的文本。

## 7. 交付前最后一道

1. 三类校对**清零**（不是"看过了"，是 grep 无输出）；抽样读每段开头、结尾各 1 章，拿第 1 段做基准确认没串味。
2. 把本批的伏笔、角色状态、时间线**一次性补进** `追踪/总表.md` 并重渲染派生文件（铁律一），再跑一次 `04-伏笔与一致性.md` 的过期扫描。

## 8. 踩过的坑

| # | 坑 | 处置 |
|---|---|---|
| 1 | 子代理把"不许改标题"理解成"不许动标题格式" | 事后用脚本统一（命令 ⑤） |
| 2 | 细纲自己写错（计数、章号、人物归属），子代理照实写 | 它反馈的矛盾要当真，逐条回改细纲/总纲 |
| 3 | 并行 Edit 同一个文件 | 同一文件的多处修改必须串行 |
| 4 | 用 here-string 合并含反引号的文本 | 用 `cat` 或脚本拷贝 |
| 5 | 每段独立贴面板、各自报数 | 数值账目表先定稿，事后按表对齐 |
| 6 | 批次太大导致后半塌篇幅 | 每批 8–10 章，逐章核字数（命令 ⑨） |
| 7 | 忘了补追踪，下一批失去真源 | 批末必做 §7 第 3 条，不隔夜 |
