# 01 · 项目与设定

覆盖九步工作流的 **① 立项 → ② 设定**，也是 ③ 卷纲之前的地基。
这层做错的代价最大：方向错了，后面 300 章全是沉没成本。

---

## 1. 立项卡（`设定/立项卡.md`）

### 填写纪律

| 纪律 | 说明 |
|---|---|
| **先判值不值得写，再写正文** | 卖点说不成一句话，就不要开书 |
| **先给卖点、冲突、故事引擎，再给大设定** | 世界观是卖点的容器，不是替代品 |
| **只补最少量澄清** | 信息够用就进下一层，不无限追问 |
| **对话里定的事必须落盘** | 方向、偏好、红线、否掉的方案写进「作者已定」；下一时刻不回翻对话 |

### 模板（可直接复制）

```markdown
# 立项卡

## 基本信息
- 书名：　题材（细分）：
- 目标平台：　目标字数：      # 短篇 <10万 / 中篇 10-50万 / 长篇 50万+
- 单章字数：      # 快节奏约 2000，均衡约 3000
- 更新节奏：      # 如 日更 2 章 / 周更 5 章
- 创建日期：

## 一句话卖点
{谁 + 在什么异常局面下 + 靠什么 + 要得到什么}

## 核心冲突与故事引擎
- 核心冲突：{谁挡着主角，为什么不能直接绕开}
- 故事引擎：{为什么这个冲突能自动跑过 100 章而不重复}
- 终极阻碍：

## 读者契约
- 读者每章来买什么：　不许背叛的三件事：

## 对标登记
| 类型 | 书名 | 取什么 | 不取什么 |
|---|---|---|---|
| 主对标 / 副对标 |  |  |  |

## 作者已定（不回翻对话）
- 偏好：　红线：　已否掉的方案：
```

## 2. 设定骨架

一题一文件，**不写成一个大杂烩**。

| 文件 | 内容 | 何时建 |
|---|---|---|
| `设定/立项卡.md` | 见上 | ① |
| `设定/题材定位.md` | 一句话梗概、主角、核心冲突、终局底牌 | ①→② |
| `设定/世界.md` | 世界骨架（只留一句，细节下沉） | ② |
| `设定/世界观/力量体系.md` | 境界、功法、代价；一题一文件 | ②，写正文时增量补 |
| `设定/金手指.md` | 若有：机制、上限、代价、冷却 | ② |
| `设定/势力/{名}.md` | 名称、定位、核心目标、关键人物、与主角关系 | 细纲当场补 |
| `设定/人物/{名}.md` | 角色静态档案（性格、口癖、来路） | ② 主角，其余增量补 |
| `设定/术语表.md` | **唯一真源**，见下节 | ②，全程维护 |

**两条硬规则**

1. **刻度必须问作者**：物价与收入量级、境界档位、金手指上限这类影响全书的数值属「先问作者」——给 1–2 个候选请作者定，确认后才落设定，不直接写死。
2. **刻度写成可数的序列**：凡是正文要拿来**比大小、算价钱、报名次、定档位**的东西，都写成「几档、哪一档在哪、相邻两档差多少」，不要只写一个孤立的值。

## 3. 术语表纪律（`设定/术语表.md`）

同物异名是长篇一致性崩坏的头号来源——写到第 200 章，模型会以为「玄铁令」和「玄铁符」是两个东西。

| 纪律 | 含义 | 违反后果 |
|---|---|---|
| **唯一真源** | 一个事物只登记一次，正文与细纲一律引用表内写法 | 检索失效、伏笔回收失败 |
| **不许同物异名** | 同一件东西不许有两个名字；换说法登记的也算 | 模型当成两个物件，剧情断裂 |
| **不许同名异物** | 两个不同东西不许撞名 | 读者困惑，AI 混线 |

### 命名避坑清单（建名时逐条过）

| 坑 | 反例 | 规避 |
|---|---|---|
| **角色姓氏撞车** | 主角「沈辞」/ 反派「沈聂」 | 主要角色姓氏不重复；同姓必须同族并写明 |
| **名字近形** | 林昭 / 林招 / 林沼 | 同卷内出现的名字，字形与拼音不得高度相近 |
| **技能名撞地名** | 功法「青云诀」vs 地点「青云峰」 | 技能、地点、势力、器物四类各占独立词域 |
| **一字之差分正邪** | 「天枢殿 / 天枢院」 | 敌对双方命名拉开语感距离 |
| **称号与真名混用** | 有时「药老」有时「陈仲」 | 登记「称号→真名」映射与使用场景 |
| **量纲漂移** | 前章 1 灵石=10 两，后文 100 两 | 量纲写进 `世界观/{主题}.md` 对照表，定了不改 |

### 术语表格式

```markdown
# 术语表
## 人物
| 规范名 | 别称/称号 | 首次出场 | 一句话定位 |
|---|---|---|---|
| 沈辞 | 无 | 第1章 | 主角，被逐出宗门的外门弟子 |

## 地点 / 势力 / 功法
| 类别 | 规范名 | 别称 | 品阶或立场 | 备注 |
|---|---|---|---|---|

## 量纲
| 项目 | 序列（低→高） | 相邻差 | 出处 |
|---|---|---|---|
| 灵石与银两 | 1 灵石 = 100 两 | — | `世界观/力量体系.md` |
```

**维护时机**：每批细纲建完后扫一遍新增具名角色/势力/设定，**会复用的当场登记**，一次性路人不登记。已存在的条目**增量补充，不覆盖**。

## 4. 目录约定（取自 story-cli）

| 规则 | 说明 |
|---|---|
| `NN-名称` | 顶级条目录用至少两位数字 + 连字符，如 `01-第一卷`、`12-玄铁篇` |
| **数值序** | `01-` < `02-` < … < `12-` < `100-`（不是字典序） |
| **序号是身份证号** | 一旦创建**不改**；改名只改后半段 |
| **`seriesOrder` 解耦展示序** | 展示序写在 `seriesOrder`（支持小数）。要在 2 和 3 之间插一章 → 写 `2.5`，**不用重排全部编号** |
| **缺失回退** | `seriesOrder` 缺失或无效，回退文件夹数字前缀 |

`.storyignore`：仓库根排除规则，`.gitignore` 简化子集（`#` 注释、`name/` 仅匹配目录、`*` 不跨目录；**不支持** `!` 取反与 `**` 递归）。草稿目录写进去：不入库但保留备份。

```text
_draft/        # 草稿目录
*.tmp          # 临时文件
.story/        # 工作区
```

保留目录（不识别为条目）：`.git`、`node_modules`、`dist`、`assets`。

## 5. 产物分级（取自 mcp-writing）

**核心边界**：手稿是「带正文附件的结构化领域模型」，不是「挂了元数据的文件夹树」。
文件夹、文件名、生成的报表都只是**表示**，不能悄悄变成领域模型本身。

| 级别 | 内容 | 谁可改 | 手改后果 |
|---|---|---|---|
| `authored_prose` | `正文/` 全部正文 | **只有写手**（审校只读） | — |
| `metadata_file` | `追踪/总表.md`、`大纲/细纲_第NNN章.md`、`设定/` | 写手 + 追踪流程 | 需按门禁流程改 |
| `sidecar` | `上下文.md`、`逐章记录/`、伏笔账本、角色状态、时间线 | **只能从总表重渲染** | **无效**，下次重渲染被覆盖 |
| `generated_export` | `导出/` 下 docx、合并稿 | 只读 | 不许手改，改了被下次导出冲掉 |

**决策测试**（动手前问）：① 动的是哪一级？② 是读、生成还是改？③ 谁拥有这个改的权限？④ 属于 sidecar → 去改总表。

## 6. 导出

| 产物 | 做法 | 级别 |
|---|---|---|
| md 合并稿 | 按 `seriesOrder` 升序拼 `正文/*.md`，章间插分隔线与章名 | `generated_export` |
| docx | md → pandoc / 本地转换，落 `导出/` | `generated_export` |
| 单卷稿 | 按 `NN-名称` 目录切片导出 | `generated_export` |

```bash
python 导出/merge.py --project 项目根 --out 导出/正文全.md   # md 合并（按数值序）
pandoc 导出/正文全.md -o 导出/正文全.docx                    # docx
```

**导出纪律**：① 导出前跑一次总表校验（`python scripts/检查.py 项目根/`），脏着的派生文件不导出；② 导出目录只进 `generated_export`，改正文后**重新导出**而非手改；③ 导出前清掉正文里的工程词（第X章、伏笔、细纲、前文），只保留章名行。
