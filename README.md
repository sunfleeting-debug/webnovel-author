# webnovel-author · 中文长篇网文创作技能包

> **一句话**：把「长篇网文怎么写才不崩」这件事，写成一份**零依赖的纯 Markdown 技能包**，
> 装进任何 AI 编程助手（Claude Code、Codex、OpenCode、WorkBuddy 等）即可使用。

它不提供服务器、不装数据库、不需要 npm install。它提供的是**纪律**：
先写纲再写文、状态只有一个真源、上下文定长、伏笔要记账、批评者不许改稿。

---

## 为什么需要它

AI 写长篇小说的失败几乎都长一个样：

- 前 20 章还能看，第 60 章开始人物ooc、伏笔烂尾、设定自相矛盾；
- 上下文越塞越满，到第 100 章时模型已经"记不住"第 3 章埋过什么；
- 角色提前说出了他不该知道的答案；
- 通篇"仿佛/似乎/像是"，一股 AI 味。

这些都不是模型能力问题，是**流程问题**。本技能包就是治这四件事的。

---

## 五条铁律

| # | 铁律 | 治什么 |
|---|---|---|
| 1 | **单一权威**：追踪总表是唯一真源，其余全是派生，手改派生无效 | 状态分裂、多头真源 |
| 2 | **细纲门禁**：没有细纲不许写正文，九字段缺一即拦下 | 边写边崩、写到哪算哪 |
| 3 | **定长上下文**：无论第几章，喂给模型的上下文卡一样大（≤12KB） | 历史膨胀、越写越忘 |
| 4 | **作者真相 ≠ 读者已知**：两条时间线分开记 | 角色提前泄底 |
| 5 | **批评者不能改稿**：写手独占产出，审校只读只诊断 | 意见污染草稿、草稿污染记忆 |

---

## 九步工作流

```
① 立项 → ② 设定 → ③ 卷纲 → ④ 细纲 → ⑤ 写正文
        → ⑥ 落追踪 → ⑦ 审校 → ⑧ 去 AI 味 → ⑨ 批量产出（长篇可选）
```

每一步的产物与门禁都写在 `SKILL.md` 里。

## 怎么用

### 1. 装进你的 AI 助手
把整个目录放进助手的 skills 目录即可（例如 WorkBuddy 是 `~/.workbuddy/skills/`，
Claude Code 是 `~/.claude/skills/`）。也可以直接把 `SKILL.md` 的内容贴进对话。

### 2. 开一本新书
对 AI 说：

> 用 webnovel-author 帮我立一本模拟类修仙长篇，目标番茄，规划五卷。

它会按 ①→③ 走：立项目卡、建目录、写设定、出卷纲。

### 3. 写某一章
> 写第 42 章。

它会先确认 `大纲/细纲_第042章.md` 存在（**没有就先补纲**，这是铁律二），
再加载定长上下文卡，写完后自动更新追踪、重渲染派生文件。

### 4. 日常体检
```bash
python scripts/检查.py <你的小说目录> --current 60
```

输出示例：
```
[3] 章号连续性
    章号范围：第 1 — 第 60 章，共 60 章
    合并稿：第一卷-正文全.md（覆盖大部分章号，属预期）
    无缺号。
    无重复。
```

## 适用与不适用

**适用**：长篇连载（几十章到几百章）、中文网文各体裁、需要跨会话保持一致的写作。

**不适用**：短篇（<5 章，直接写更快）、诗歌、非虚构、需要多人实时协作的场景。
